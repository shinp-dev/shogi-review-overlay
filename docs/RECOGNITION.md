# 将棋ウォーズ盤面画像比較（v0.3.0）

## 認識アルゴリズム

1. 盤面調整済みの9×9の各マスを検査する。線の混入を避けるため、**上下左右の外周8%を除外**し、残り84%を32×32に最近傍サンプリングする。
2. 輝度（77R+150G+29B）/256 が115未満の画素を黒、それ以外を白とする。81マスの特徴量はフレームの1回の画素配列取得で計算する。
3. 32個の横方向黒画素数と32個の縦方向黒画素数（64要素）で16種類の先後別の基本駒テンプレートを比較し、上位6種だけ32×32のビット配置で再確認する。評価式は縦横プロフィールcosine 55%＋画素cosine 45%。
4. 黒画素70未満は空きマス。最高一致度0.74未満、または2位との差0.075未満のマスは未確定として局面解析を拒否する。
5. 盤上40枚のケースは王将・駒種別合計を検査してSFENへ。持ち駒が生じている場合は確定済みの前局面から1手の合法手差分で復元する。復元不能な局面はSFENを手入力する。
6. やねうら王Material版にUSI MultiPV=1〜3で渡す。対局中に見える投了ボタン色を検出した場合は候補を表示しない。

画像比較に使う素材は app/src/main/assets/shogi_templates_v1.txt。ユーザーが共有した将棋ウォーズ初期盤面の**駒セルから抽出した32×32の白黒パターンのみ**を格納。元画像や対局者名・UI全体の画像は含まない。

## 実測・制限

- 提供された同じ将棋ウォーズテーマの初期盤面・数手進めた盤面の2画像を用い、Pythonによる同条件の画像比較で盤上の駒種・位置を正しく分類した。別テーマ、画面倍率、アニメーション、成駒では未検証。
- 盤中央の「先手」「後手」などの文字装飾は低一致度・低黒画素数で誤認識を避ける。ただし別の大きな装飾や駒デザイン変更では判定できない可能性がある。
- 成駒の画像テンプレートは未登録。持ち駒領域も現在は直接分類せず、合法手1手の履歴追跡に依存する。
- 認識が未確定の局面で推奨手を勝手に出さず、表示を消す。誤認識防止を速度より優先する。
- Android上の動作・バッテリー消費・認識時間は実機で未測定。
- 盤面は画面下が先手の向き専用。対局中と振り返りの厳密な識別は未実装。
