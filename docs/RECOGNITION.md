# 将棋ウォーズ・将棋クエスト盤面画像比較

## 認識アルゴリズム

1. 盤面調整済みの9×9の各マスを検査する。線の混入を避けるため、**上下左右の外周8%を除外**し、残り84%を32×32に最近傍サンプリングする。
2. 輝度（77R+150G+29B）/256 が115未満の画素を黒、それ以外を白とする。81マスの特徴量はフレームの1回の画素配列取得で計算する。
3. 32個の横方向黒画素数と32個の縦方向黒画素数（64要素）で先後別テンプレートを比較する。将棋ウォーズは基本駒16種＋成駒12種、将棋クエストは基本駒16種。基本駒には別画面の補助テンプレートも登録し、**駒種単位で上位6種**を選び、その駒種に属する全テンプレートの最良一致を利用する。評価式は縦横プロフィールcosine 55%＋画素cosine 45%。
4. 黒画素70未満は空きマス。最高一致度0.74未満、または2位との差0.075未満のマスは未確定として局面解析を拒否する。
5. 盤上40枚のケースは王将・駒種別合計を検査してSFENへ。持ち駒が生じている場合は確定済みの前局面から1手の合法手差分で復元する。復元不能な局面はSFENを手入力する。
6. 検出位置は初期設定グリッドを中心に最大±4実画面ピクセルで探索。2px間隔の粗探索→周囲1pxの微調整で、81マス全体の信頼度・王将・駒数整合性から採用する。採用したdx/dyは手動位置設定に加算せず別管理し、矢印・候補表示の座標にのみ反映する。局面やエンジンが不確実な場合は候補を消す。
7. やねうら王Material版にUSI MultiPV=1〜3で渡す。投了ボタンの有無による認識停止は行わない（対局後の振り返りでのみ使用すること）。

画像比較に使う素材は app/src/main/assets/shogi_templates_v1.txt（将棋ウォーズの既存基本駒）・shogi_wars_variants_v1.txt（ウォーズ別画面の基本駒）・shogi_wars_promoted_v1.txt（ウォーズ成駒）・shogi_quest_templates_v1.txt（将棋クエスト）。ユーザー提供の振り返り画面から**駒セルのみを32×32白黒パターンに抽出**。元画像、対局者名、UI全体の画像は格納しない。アプリ選択に応じてテンプレートを切り替え、手動盤面位置と自動補正も別々に保存する。

## 将棋クエストの初期対応

- 提供された691×1536の9路レビュー画面の枠を基準に、初期位置（left=0.012, top=0.179, width=0.977, height=0.480）を設定。画面サイズやバナーによってズレるため、初回は手動調整が必要。
- スクリーンショットの盤上34枚について、32×32の輝度マスク比較をオフライン検査し、基本駒種と向きが判別できることを確認（Android実機は未検証）。
- 先後の香・桂・銀・金・玉／王・飛・歩は盤上の実画素、角は持ち駒領域の画像を切り出して仮登録。持ち駒角は盤上角と大きさが違うため、角の認識は保証しない。
- 盤上に成駒がある局面、別の駒テーマ、盤面の上下反転、途中局面からの持ち駒復元は未対応。振り返りは初期局面から1手ずつ再生する必要がある。


## 実測・制限

- 将棋ウォーズについては既存の初期盤面・数手進めた盤面の2画像に加え、今回の成駒6種類を含む691×1536画像から抽出した81マスの白黒マスクを照合。盤上31枚の駒種・先後・成り状態と空白50マスを検証した。別の端末倍率、アニメーション、後手成駒の実画像では未検証。
- 盤中央の「先手」「後手」などの文字装飾は低一致度・低黒画素数で誤認識を避ける。ただし別の大きな装飾や駒デザイン変更では判定できない可能性がある。
- 将棋ウォーズの成駒6種（と、成香、成桂、成銀、馬、龍）を追加。画像の先手向き駒から抽出し、後手向きは180度回転で仮生成した。**後手成駒の実画像照合は未検証**。将棋クエストの成駒は未対応。持ち駒領域も現在は直接分類せず、合法手1手の履歴追跡に依存する。
- 認識が未確定の局面で推奨手を勝手に出さず、表示を消す。誤認識防止を速度より優先する。
- Android上の動作・バッテリー消費・認識時間は実機で未測定。
- 盤面は画面下が先手の向き専用。対局中と振り返りの厳密な識別は未実装。
