# Shogi Review Overlay

将棋ウォーズなどの**対局後の振り返り画面**に、候補手を重ねるAndroidアプリ（試作版）。

## 実装済み（v0.4.1・試験中）

- AndroidのMediaProjection許可で画面全体を取得し、各マスの外周8%を除外して32×32白黒画像比較。上下左右それぞれ最大4pxの盤面位置ズレを自動探索・補正
- 設定画面で**将棋ウォーズ／将棋クエスト**を選択。盤面位置・補正値はアプリ別に保存し、各アプリ専用の駒画像テンプレートを利用
- 盤面を9×9に手動調整。クエストは上下各9候補枠の金色の駒形を検出、ウォーズは上下最大7枠のオレンジの駒形を検出。駒がある枠内だけで駒種・先後・枚数を判定し、持ち駒が復元できなければ従来どおり1手差分で追跡
- やねうら王 MaterialLv1 をAndroid arm64-v8a向けにビルドしてAPKへ同梱
- USI MultiPV=1〜3で候補と評価値を取得し、緑/青/橙の盤面矢印と候補一覧に表示
- 将棋ウォーズ・将棋クエストともに成駒6種類×先後2方向の画像照合に対応。ウォーズは後手向き全6種、クエストは後手向き馬以外5種が回転画像による暫定テンプレート。通常駒は以前のテンプレートも併用
- SFEN手入力による補正、文字サイズ・思考時間などの設定
- 通常時はタップ透過で、調整画面と同じ緑色の盤面外枠を候補手がないときも表示。位置補正後の枠・矢印は同じ座標へ移動し、画面認識失敗時は候補のみ消去（画面取得の瞬間は一時非表示）

## 注意事項

- やねうら王は**Material評価版**。NNUE評価関数は未搭載で、候補の質は高性能版と同等ではない。
- 画像比較の実機認識率とMediaProjectionの操作動作はまだ未検証。両アプリとも基本駒16種＋成駒12種を照合するが、持ち駒が多数ある局面、複数手飛ばしはSFEN手動補正が必要な場合がある。
- 将棋クエストは提供された2枚の振り返り画像で、通常駒34枚と成駒を含む32枚の認識を回帰テスト。さらに提供された3枚の画像から上下各9候補枠の金色画素だけを抽出し、**離れた位置に並ぶ持ち駒も含めて位置認識を検証**。枚数の赤い数字は**2・3・6が実画像由来、ほかは仮の合成テンプレート**。数字の判定に失敗しても、盤上の不足駒と持ち駒の所有者から枚数が一意に決まるときだけ補完する。駒種別の40枚が整合しなければ解析を見送り、一手差分追跡に戻る。別テーマ・実機・未撮影の後手成駒は未検証。
- 将棋ウォーズの持ち駒画像認識は初期対応。実画像から確認した後手の角・歩と先手の歩・香・金、黄色い枚数2・3のみ登録済み。未収集の持ち駒や別テーマは検出できない場合があり、駒種別の総数が40枚と一致しなければ途中局面として採用しない。実機では未検証。
- **対局後の振り返り専用**。投了ボタン検出による停止は廃止しました。対局中/振り返り画面の判別は行わないため、対局中には起動しないでください。
- スクリーンショットは端末からアップロードしない設計。
- GPLv3ライセンスと上流の対応ソース提供条件について、配布前の整合性確認が必要。

詳しくは docs/ENGINE.md と docs/RECOGNITION.md を参照。

## ビルド
JDK 17・Android SDK API 35・Gradle 8.9、Native版をビルドする場合はAndroid NDK r23bが必要です。GitHub Actionsは同梱まで実施します。

```bash
gradle :app:assembleDebug
gradle :app:testDebugUnitTest
```

成果物は `app/build/outputs/apk/debug/app-debug.apk`。

## 使い方

1. インストール後、他のアプリの上に表示する権限を許可する。
2. 設定画面で**将棋ウォーズ**か**将棋クエスト**を選択し、対象の対局後振り返りで盤面位置を手動調整する。
3. アプリで「盤面を自動認識・解析」を押し、Androidの画面全体の共有を許可する。
4. 対象アプリの振り返りを開いたまま局面を1手ずつ進める。3候補を再解析する。
5. 認識に失敗した場合、設定画面の最新ステータスを確認し、必要ならSFENを手動入力して再解析する。
6. 終了したら「自動認識を停止」と「オーバーレイ停止」を押す。
